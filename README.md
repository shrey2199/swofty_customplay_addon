# Custom Play Addon for Swofty Launcher

Custom Play adds an alternate way to launch F1 25 through the official Swofty Launcher. It uses the game folder and profile selected in the launcher, then starts a `.bat` or `.exe` loader you choose.

## Install from Releases

1. Open [Custom Play releases](https://github.com/shrey2199/swofty_customplay_addon/releases) and download the `.swoftyaddon` file from the latest release's **Assets** section.
2. Install it by dragging the downloaded file onto Swofty Launcher, or open the launcher's **Addons** page and install the file there.
3. Select your F1 25 game folder and the profile you want to use. On the **Addons** page, enable **Custom Play** for that profile.

## Use the Addon

1. Open **Custom Play** from the launcher's sidebar.
2. Choose **Loader file** and select your `.bat` or `.exe` file which you use to open the game usually without mods. The loader runs with the selected F1 25 game folder as its working directory, so relative paths in the loader resolve from that folder.
3. Click **Play Custom**. Custom Play prepares the selected profile's mods, starts your loader, and keeps the session active until F1 25 closes. The launcher then restores the game files.
4. Use **Open launch log** on the Custom Play page to inspect the session output if needed.

The addon updates separately from Swofty Launcher. When a Custom Play update is available, the page shows the release notes under **What's New** and offers **Update Custom Play**. The updater shows download progress and restarts Swofty to install the update. A launcher-version warning or available update does not disable **Play Custom**.

## Building the Addon Yourself

This repository builds the Windows x64 Custom Play addon and its patched `swofty.exe` from a tagged [Swofty Launcher release](https://github.com/Swofty-Developments/SwoftyLauncher/releases).

## Build on Windows

Install PowerShell 7.2 or newer, Git for Windows, Rust via rustup, and the Visual Studio C++ build tools with a Windows SDK. Rustup uses the toolchain pinned by the upstream release. Internet access is needed for the default build to fetch Swofty and any uncached Rust dependencies.

From this folder, run the latest stable release build or select a release tag explicitly.

```powershell
pwsh -NoProfile -File ./Build-CustomPlay.ps1 -AddonOnly
pwsh -NoProfile -File ./Build-CustomPlay.ps1 -Tag v1.8.6 -AddonOnly
```

The script checks out the release tag, checks and applies `patches/custom-play-cli.patch`, verifies the official Windows ZIP against the release's `SHA256SUMS`, then builds the CLI and the addon helper with their lockfiles. It runs the Custom Play session tests with a stand-in game process. Both packages use the native loader and DXC from the same release.

Successful builds go in `dist/<tag>/`.

- `local.custom-play-<version>-windows-x64.swoftyaddon` is the installable addon. Its version follows the upstream tag so successive builds can update the same addon ID.
- Omit `-AddonOnly` to also create `custom-play-runner-<tag>-windows-x64.zip` for standalone use. Keep `bin/`, `loader/`, and `dxc/` together when extracting it.
- `SHA256SUMS` covers the packages generated by the build. `BUILD_INFO.json` inside each package records the upstream commit and the hashes of the patch and original Windows ZIP.

Drag the `.swoftyaddon` into the matching official launcher, enable **Custom Play** for your profile, and open **Custom Play** in the sidebar. Choose your `.bat` or `.exe` under **Loader file** and click **Play Custom**. The loader runs with the selected game folder as its working directory. **Open launch log** shows the session output.

## Publish and install addon updates

GitHub Actions checks hourly for the latest stable Swofty release and builds the addon when that Swofty version has no published Custom Play package. Use **Actions → Release Custom Play addon → Run workflow** on `main` to check immediately. If GitHub disables scheduled runs after 60 days of public repository inactivity, re-enable the workflow from the Actions tab.

To publish an addon-only patch, push a commit to `main` that starts with `releasecommit:`. For example, `releasecommit: Fix the update notice` uses “Fix the update notice” and any commit body as the release notes. Both paths share the same release queue, attach only the `.swoftyaddon`, and clean up the temporary Windows build data.

For a manual addon-only build on a specific Swofty release, use `-Tag` and `-AddonPatch`.

```powershell
pwsh -NoProfile -File ./Build-CustomPlay.ps1 -Tag v1.8.6 -AddonPatch 1 -AddonOnly
```

Publish `dist/v1.8.6_patch1/local.custom-play-1.8.6_patch1-windows-x64.swoftyaddon` on the `v1.8.6_patch1` tag in [the Custom Play repository](https://github.com/shrey2199/swofty_customplay_addon/releases). Keep the generated asset name and enter the changes in the GitHub release description. Use `v1.8.6_patch2` for the next addon-only update, or the plain upstream version tag when moving to a newer Swofty release. The addon manifest uses a valid SemVer version such as `1.8.6+patch.1`.

Install the first updater-enabled build manually. The sidebar then checks GitHub in the background and shows the available release's notes under **What's New**. **Update Custom Play** shows download progress, verifies the package, and restarts Swofty to install it. If Swofty can't close automatically, the sidebar asks you to close it. A newer launcher version or an available update leaves **Play Custom** enabled. The update log is saved as `updates/update.log` in Custom Play's addon data folder.

## Check or rebuild a release

```powershell
pwsh -NoProfile -File ./Build-CustomPlay.ps1 -Tag v1.8.6 -CheckPatch
```

`-CheckPatch` needs Git and PowerShell only. If an upstream change conflicts with the patch, the build stops before compiling or packaging. Update the patch for that tag and run a full build to validate it. An existing output folder for a tag is preserved. Use `-OutputDirectory` to build another copy.

To use a local upstream Git repository and a previously downloaded official ZIP, pass both paths and an explicit tag. The local repository must contain the tag. Check the local ZIP against the upstream checksum before supplying it. `-RustToolchain stable` can override the upstream Rust pin when you have a compatible toolchain installed.

```powershell
pwsh -NoProfile -File ./Build-CustomPlay.ps1 -Tag v1.8.6 `
  -SourceRepository 'C:\path\to\SwoftyLauncher' `
  -ReleaseZip 'C:\downloads\swofty-launcher-v1.8.6-windows-x86_64.zip'
```

## Repository contents

- `Build-CustomPlay.ps1` is the manual build entry point.
- `patches/custom-play-cli.patch` contains the changes to the CLI and shared launch configuration, including the Windows custom loader session tests.
- `addon/` contains the helper source, its Cargo lockfile, and the addon manifest template.

This folder is the repository root. Git ignores downloaded sources, build intermediates, and generated packages. The generated packages include upstream third-party notices.
